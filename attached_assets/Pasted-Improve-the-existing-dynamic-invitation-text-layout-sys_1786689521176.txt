Improve the existing dynamic invitation text layout system.

IMPORTANT:
Do not redesign the invitation.
Do not change the background, ornaments, flowers, decorations, colors, or overall composition.

The problem:
Dynamic text can have different lengths depending on the customer's input. For example:

Groom: Nasser
Bride: Alia

can become:

Groom: Muhammad Hakim
Bride: Nur Aisyah Sofea

The text must automatically adapt without overlapping other elements or looking badly positioned.

Implement this using the EXISTING codebase and existing text-rendering system.

Requirements:

1. Keep each design's original positioning and visual style.

2. Create a reusable responsive text layout system for dynamic fields.

3. Dynamic fields should support:

* title
* groom name
* bride name
* "&"
* day
* date
* venue
* hashtag
* other existing dynamic text fields

4. For the couple names, treat Groom + "&" + Bride as one `coupleGroup`.
   The entire group should stay centered and vertically balanced.

5. Do NOT rely only on fixed `top` / `left` coordinates for dynamic text.

6. Each text field should have layout constraints such as:

* maxWidth
* minWidth
* fontSize
* minFontSize
* lineHeight
* maxLines
* textAlign
* spacing

7. When text is longer:

* first reduce font size within the allowed range
* then wrap if allowed
* maintain center alignment
* maintain spacing between sections
* prevent overlap

8. Add safe-area / boundary detection.
   Dynamic text must not overlap:

* flowers
* ornaments
* decorative frames
* other text
* important visual elements

9. Do not globally change every design.
   Each invitation design should be able to have its own text layout configuration because different designs have different available spaces.

10. Make the solution backward-compatible with the current designs.

11. Do not create a completely new editor or rendering architecture.
    Modify the existing implementation and reuse the current components/functions wherever possible.

12. Before changing code:

* inspect the existing dynamic text implementation
* identify how text positions, font sizes, and design configurations are currently stored
* identify the preview/rendering component
* then implement the responsive layout logic in the appropriate existing files

13. Test with these examples:

Short:
Groom: Nasser
Bride: Alia

Medium:
Groom: Muhammad Hakim
Bride: Nur Aisyah

Long:
Groom: Muhammad Hakim Bin Abdullah
Bride: Nur Aisyah Sofea Binti Ahmad

The long version must still look balanced and must not overlap other elements.

IMPORTANT:
Preserve the current appearance for short/default text. The existing design should look exactly the same when using the original text.

After implementation, show me which files were changed and briefly explain how the new dynamic layout works.
